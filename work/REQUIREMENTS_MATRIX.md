| Review gate | Evidence needed before a warehouse claim |
|---|---|
| Release/access | Approved read access, manifest/build identifier, actual schemas, verified counts/date bounds and local cache rules; no token or private output in public files |
| Daily grain / joins | No duplicate `(report_date, client, content)` facts; dimension keys unique; before/after join row counts and unmatched-key counts; no multiplication by query rows; one row per `(client, content, decision date)` in the model frame |
| Decision timeline | Fixed half-open windows; for final June, decision `2026-06-01 00:00`, features `[2026-03-03, 2026-06-01)`, reference `[2026-05-02, 2026-06-01)`, outcome `[2026-06-01, 2026-07-01)`; “May 31 decision” must mean after the day closes |
| Historical fields | Feature availability at the decision is proved. Current snapshot depth, update/freshness, tiers/status and other mutable dimension metadata cannot be backdated. A fact-only first model is safer; creation timestamps require valid historical semantics and must not postdate the decision |
| Coverage/availability | Actual three-valued GSC/GA4 flags handled with `IS TRUE`; false/null/untracked dates are not measured zero traffic. Missing daily rows are not zero without explicit release semantics. Prior and target coverage thresholds are fixed before final outcome inspection |
| Eligible population | Minimum volume and enough history are defined from prior data only. No filter for positive June volume or survival into June. Undefined/incomplete labels and any required future-coverage exclusions are counted and disclosed as selection limitations |
| Future label | A frozen decline rule compares future impression rate with prior-reference rate using usable observed days; reject zero/low prior denominators. Volume, coverage, decline cutoff and uncertainty policies are explicit. A future decline label still does not measure useful edits or causal refresh benefit |
| Ratios/position | CTR is summed clicks / summed impressions; position is impression-weighted over usable, measured positions. Do not average daily percentages/position blindly. GA4-based features use only observed GA4 dates and retain availability/coverage indicators |
| Query table | Default exclude the fixed recent 90-day query snapshot from prospective features. Any exception proves exact prior-only window alignment. Per-content repeated context is deduplicated/`ANY_VALUE`, never summed as if each query row were independent content |
| Sealed outcome | March supports query development; the final-month `_sample` is June and is not a development fallback. Commit a frozen feature/label/split/model contract plus a reproducible frame builder before final outcome evaluation; retain hashes and execution receipts |
| Split meaning | State whether the claim is future performance on existing clients, unseen clients, or both. A joint claim needs client disjointness across all development months and a future test month. Training/validation outcomes must finish before their next prediction date; purge/embargo overlapping target intervals where needed |
| Model comparison | Fit imputers, scales, encoders, thresholds and CDF transformations within development only. Model selection uses validation; compare rule/models on identical final rows and do not switch the chosen model based on June scores |
| Metrics / decisions | Coverage/exclusion counts, per-split base rates, AP, precision/recall at effective K, client macro metrics, bounded cluster uncertainty and failure cases. Top-20 ranked examples support human inspection, not a claim of completed authorized content review |
| Cost/claim limits | Review time and error tradeoffs may be qualitative. No invented money/ROI, production readiness, Google-factor claim, causal impact or automatic editorial utility. Report modest or negative results honestly |

## Data and publication constraints

The anonymized starter slice is the only allowed dataset CSV, along with the provided small `outputs/refresh_queue_sample.csv` exception in CI. New CSVs, Parquet files, archives and bulk extracts must not be committed. Markdown summary tables, charts and compact metrics JSON receipts are suitable public artifacts. Do not silently add ignore rules that hide metrics JSON.

Data may be inspected locally. Do not send row-level client data to unapproved cloud tools. Pseudonymous IDs may support joins, grouped validation and carefully scoped review lists; they cannot be used as predictive features or reverse-mapped. Rates are percent units; zero position means unavailable. Starter `trend_direction`/`trend_pct` determine `is_declining_label` and cannot be features of that label. A snapshot proxy classifier does not forecast future decline or prove refresh impact.

The warehouse is gated. Freestyle or genuine future-window prediction requires permitted warehouse access and observed temporal data; fake warehouse extracts or invented results cannot fill that gap. Official predefined lane guidance explicitly permits starter data for several lanes and is internally broader than the capstone card's warehouse emphasis. Any starter capstone must state that choice and its limitations.

Publication, configured account screenshots, Academy completion, calendar reminder installation, domain ownership, badges and showcase/portal submissions require actual user/account evidence. They remain outstanding until independently evidenced. A saved local recurring reminder note can be verified from its real file and does not require calendar access under the pasted brief.
