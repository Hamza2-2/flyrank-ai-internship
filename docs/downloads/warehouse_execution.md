`plan` and `self-check` need no token or warehouse access. Other remote stages read the local Hugging Face saved login or `HF_TOKEN` through `huggingface_hub.get_token()`. Accept the FlyRank gate in your own account first, and use a read token locally. Never pass a token as a command argument, paste it into notebook source, or publish it. Secret creation uses an in-memory DuckDB secret and suppresses credential-bearing exception text. The script fails with a sanitized pending/stopped message if auth or actual schema is unavailable; that is not successful warehouse execution.

`inspect` verifies the actual March daily schema and client schema, March row/date bounds, null keys/dates, metric quality, duplicate daily grains, and one-to-one client-dimension keys. Required daily fields are `report_date`, `client_hash_id`, `content_hash_id`, `gsc_impressions`, `gsc_clicks`, `gsc_avg_position`, and `gsc_data_available`; required client fields are `client_hash_id` and `gsc_data_start`. These are contract requirements awaiting verification, not claimed inspected types. Missing fields stop the pipeline rather than quietly substituting assumptions. Both false and null tracking flags are unobserved. Nonfinite/negative metric values are counted and excluded.

`develop` executes the exact aggregation on March 2026 only. It validates query mechanics and duplicate handling, never June outcomes or model quality. `aggregate` reads the non-June release partitions, projects only needed fields, pushes exact study-date limits into DuckDB, and saves page-at-decision aggregates. The source is pinned to public metadata revision `50cbf7c3909d07be4d1b5906b4d09e882e5acbf2`. Whole-source counts and date bounds are audits; projection/aggregation avoids bringing daily raw rows into pandas. Full feature and June outcome scans are disjoint and cached; metadata/grain/quality audits are additional diagnostic reads. If HTTP 429 occurs, stop rather than hammer the host or switching to the June sample.

For decision midnight **D=2026-06-01**, features are **[D−90 days,D)**, the prior reference is **[D−30 days,D)**, and the sealed outcome is **[D,D+30 days)**, June 1–30. Earlier training decisions are 2025-12-01 and 2026-02-01; validation is 2026-04-01. The last training outcome ends on March 3, before the April decision; validation ends May 1, before the June decision. Client groups are disjoint across train, validation and final test, so the claim concerns future outcomes on unseen clients, rather than a row-random split. Calendar-month lengths do not silently change these fixed 30/90-day windows.

Pre-decision eligibility requires known client history by D−90, 72 usable feature days, 24 usable days in each prior 30-day segment, at least 100 prior-reference impressions, and a finite positive prior daily rate. The target is a future observed daily-impression rate below 80% of the prior daily rate, requiring at least 24 usable future days. Unavailable/missing target days are not zero; an adequately observed zero-impression future is a valid decline. No positive future volume, surviving-page status, content snapshot, or fixed-90-day query filter selects candidates. Outcome coverage changes the evaluation population and is reported as attrition. Recommendations use the full prior-eligible test pool, including undefined-outcome candidates.

`freeze` selects between two fixed models on validation average precision, refits development only, and records a contract/code/model/cache hash. The baseline is a **new prior-only historical-momentum, visibility and measured-position rule**, distinct from the starter freshness/depth rule. CTR is derived as sum clicks/sum impressions ×100 on complete observed-click coverage; positions use impression weighting, never a mean of daily means. Current content metadata and fixed-window query tables are omitted because their historical availability is unproved. Row order is stable before seeded sampling or tie handling. Training fitting is capped at a predetermined random sample of 250,000 rows, with both-class checks and sample counts recorded.

`evaluate` first verifies the frozen code, policy, model artifact and client/development cache hashes, then writes a private access marker before any June query. A June marker prevents refreezing even if freeze artifacts are deleted. It reads June once, reconciles total daily facts to the expected 78,835,655, and compares frozen models and baseline on the same outcome-observed subset. It reports base rates, effective K, per-client/macro metrics, group uncertainty, cohort exclusions and bounded synthetic review cases. No refresh benefit or causal algorithm claim follows from future-outcome discrimination.
